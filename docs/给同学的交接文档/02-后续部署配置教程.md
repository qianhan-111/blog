# 后续部署配置教程

这份文档接在 `01-文件接收入手教程.md` 后面看。目标是把项目部署到你自己的 GitHub、Neon 和 Vercel，不沿用原作者账号或密钥。

## 1. 准备账号

你需要自己准备：

```text
GitHub 账号：待填写
Neon 账号：待填写
Vercel 账号：待填写
```

账号登录、邮箱验证、浏览器授权和网页后台点击，需要账号本人完成。协助排查时可以发日志和截图，但涉及 `DATABASE_URL`、`JWT_SECRET`、数据库密码、Vercel token 时要先打码。

## 2. 上传到自己的 GitHub 仓库

在 GitHub 创建一个新仓库，建议仓库名用：

```text
blog
```

创建仓库时不要勾选自动生成 README、`.gitignore` 或 license。

在项目根目录检查远程仓库：

```powershell
git remote -v
```

如果这里没有输出，添加你自己的仓库地址：

```powershell
git remote add origin https://github.com/<你的GitHub用户名>/blog.git
```

然后推送当前分支。当前项目通常是 `master`：

```powershell
git push -u origin master
```

如果你改成了 `main`，就执行：

```powershell
git push -u origin main
```

## 3. 创建 Neon 数据库

在 Neon 创建 PostgreSQL 项目后，保存两条连接字符串：

```text
direct 连接字符串：本地执行 db:migrate 和 db:seed 用，待填写
pooled 连接字符串：Vercel 的 DATABASE_URL 用，待填写
```

通常 direct 连接字符串的主机名不带 `-pooler`，pooled 连接字符串的主机名带 `-pooler`。

## 4. 初始化数据库

如果已经按上一份文档创建了 `.env.local` 并填写 direct `DATABASE_URL`，直接执行：

```powershell
npm run db:migrate
npm run db:seed
```

如果你不想写 `.env.local`，也可以在 PowerShell 临时设置：

```powershell
$env:DATABASE_URL="<你的 Neon direct 连接字符串>"
npm run db:migrate
npm run db:seed
Remove-Item Env:\DATABASE_URL
```

建议在执行 `db:seed` 前设置自己的初始化账号：

```powershell
$env:SEED_ADMIN_USERNAME="<你的管理员用户名>"
$env:SEED_ADMIN_EMAIL="<你的管理员邮箱>"
$env:SEED_ADMIN_PASSWORD="<你的管理员密码>"
$env:SEED_AUTHOR_USERNAME="<你的作者用户名>"
$env:SEED_AUTHOR_EMAIL="<你的作者邮箱>"
$env:SEED_AUTHOR_PASSWORD="<你的作者密码>"
npm run db:seed
Remove-Item Env:\SEED_ADMIN_USERNAME, Env:\SEED_ADMIN_EMAIL, Env:\SEED_ADMIN_PASSWORD, Env:\SEED_AUTHOR_USERNAME, Env:\SEED_AUTHOR_EMAIL, Env:\SEED_AUTHOR_PASSWORD
```

如果没有设置 `SEED_*`，项目会创建默认演示账号。默认账号适合临时验收，不适合长期使用。

## 5. 导入到 Vercel

在 Vercel 里选择 `Add New Project`，从 GitHub 导入刚才的仓库。

确认配置：

| 配置项 | 值 |
| --- | --- |
| Framework Preset | `Vite` |
| Install Command | `npm ci` |
| Build Command | `npm run build` |
| Output Directory | `dist` |
| Node.js Version | `24.x` |

项目根目录已有 `vercel.json`，会处理 `/api/*` 接口和前端页面刷新回退。

## 6. 配置 Vercel 环境变量

在 Vercel 项目的 `Settings -> Environment Variables` 里添加：

```dotenv
DATABASE_URL=<你的 Neon pooled 连接字符串>
JWT_SECRET=<至少 32 个字符的随机字符串>
JWT_EXPIRES_IN_SECONDS=86400
VITE_API_BASE_URL=/api
VITE_APP_TITLE=Blog Platform
VITE_INDEXING_ENABLED=false
VITE_OBSERVABILITY_ENABLED=false
```

可选变量：

```dotenv
VITE_SITE_URL=<部署成功后的 https 生产网址>
VITE_OBSERVABILITY_DSN=<只有启用观测时才填>
VITE_RELEASE_VERSION=<提交号或 v1.0.0；通常可由 Vercel 系统环境变量自动提供>
```

第一次部署可以先不填 `VITE_SITE_URL`。部署成功后，把最终生产网址补到 `VITE_SITE_URL`，再重新部署一次。

如果 Vercel 有 `Automatically expose System Environment Variables` 开关，建议打开，让项目自动读取 `VERCEL_ENV`、`VERCEL_URL`、`VERCEL_PROJECT_PRODUCTION_URL` 和 `VERCEL_GIT_COMMIT_SHA`。

## 7. 部署

环境变量保存后点击 `Deploy`。

如果环境变量后续改过，要在 `Deployments` 页面重新 `Redeploy`，旧部署不会自动读取新变量。

## 8. 上线后验收

把下面的 `<你的网址>` 换成 Vercel 生产网址：

```text
<你的网址>/api/health
<你的网址>/api/categories
<你的网址>/
<你的网址>/login
<你的网址>/admin/login
<你的网址>/robots.txt
<你的网址>/sitemap.xml
<你的网址>/site.webmanifest
```

最低验收标准：

1. `/api/health` 返回 JSON，并且包含 `"status":"ok"`。
2. `/api/categories` 返回 JSON，并且 `code` 为 `0`。
3. 首页能打开并看到文章列表。
4. 作者账号能登录、创建草稿、发布文章。
5. 管理员账号能登录后台，文章、分类、标签、用户列表能加载。
6. 刷新 `/articles/任意文章ID`、`/login`、`/admin/articles` 这类前端路由不会 404。
7. `robots.txt`、`sitemap.xml`、`site.webmanifest` 返回正确文本，不是首页 HTML。

## 9. 失败时怎么发给别人排查

可以发：

- Vercel 构建日志最后 30 行。
- 公开 Vercel 网址。
- `/api/health` 和 `/api/categories` 返回内容。
- 浏览器报错截图。
- 本地执行失败命令的最后 30 行输出。

不要直接发：

- 未打码的 `DATABASE_URL`。
- 未打码的 `JWT_SECRET`。
- `.env.local` 文件。
- Neon、Vercel、GitHub 的登录 token。

确实临时暴露真实值后，要在 Neon 或 Vercel 重新生成并替换。
