# 文件接收入手教程

这份文档是给接手项目的人看的。你收到压缩包后，先按这里把项目在本机整理好，再继续看 `02-后续部署配置教程.md`。

## 1. 解压项目

把压缩包解压到一个路径简单、最好全英文的目录，例如：

```text
D:\projects\blog
```

不要直接在压缩软件里运行命令。先完整解压，再用 VS Code 打开解压后的项目文件夹。

## 2. 先确认不要误用原作者信息

项目里不应包含原作者的真实登录账号、数据库连接字符串或部署密钥。你需要自己准备并填写：

```text
GitHub 账号：待填写
Neon 数据库账号：待填写
Vercel 账号：待填写
DATABASE_URL：待填写，不能公开
JWT_SECRET：待填写，不能公开
管理员账号：待填写或由 db:seed 创建
作者账号：待填写或由 db:seed 创建
```

不要把 `.env.local`、数据库连接字符串、`JWT_SECRET`、Vercel token 或任何真实密码发给别人，也不要提交到 GitHub。

## 3. 安装 Node.js

本项目要求 Node.js 24.x。打开 PowerShell 后执行：

```powershell
node -v
```

如果输出不是 `v24.x.x`，先安装 Node.js 24.x，再继续。

## 4. 安装依赖

在项目根目录打开 PowerShell，确认当前位置是项目目录：

```powershell
Get-Location
```

然后安装依赖：

```powershell
npm ci
```

如果这里失败，把终端最后 30 行错误发给协助排查的人。不要只发截图里的一小段。

## 5. 准备本地环境变量

复制环境变量模板：

```powershell
Copy-Item .env.example .env.local
```

打开 `.env.local`，至少填好这些值：

```dotenv
DATABASE_URL=<你的 Neon direct 数据库连接字符串>
JWT_SECRET=<至少 32 个字符的随机字符串>
JWT_EXPIRES_IN_SECONDS=86400
VITE_API_BASE_URL=/api
VITE_APP_TITLE=Blog Platform
VITE_SITE_URL=http://localhost:5173
VITE_INDEXING_ENABLED=false
VITE_OBSERVABILITY_ENABLED=false
VITE_OBSERVABILITY_DSN=
VITE_RELEASE_VERSION=local

SEED_ADMIN_USERNAME=<你的管理员用户名>
SEED_ADMIN_EMAIL=<你的管理员邮箱>
SEED_ADMIN_PASSWORD=<你的管理员密码>
SEED_AUTHOR_USERNAME=<你的作者用户名>
SEED_AUTHOR_EMAIL=<你的作者邮箱>
SEED_AUTHOR_PASSWORD=<你的作者密码>
```

`SEED_*` 是初始化数据库时创建账号用的。建议你填自己的管理员和作者账号，避免继续使用默认演示账号。

可以用下面命令生成一个可用的 `JWT_SECRET`：

```powershell
[Convert]::ToBase64String((1..48 | ForEach-Object { Get-Random -Maximum 256 }))
```

把输出完整复制到 `JWT_SECRET=` 后面。

## 6. 跑项目检查

先跑完整检查：

```powershell
npm run verify
```

这个命令会依次检查代码规范、单元测试、后端测试、冒烟测试和生产构建。通过后再继续部署。

如果你只是想先看页面，可以执行：

```powershell
npm run dev
```

注意：`npm run dev` 主要用于查看前端页面。完整登录、发文、后台和线上接口，以部署到 Vercel 后的结果为准。

## 7. 你接下来该看什么

建议阅读顺序：

1. 当前文档：先把项目解压、依赖、环境变量和本地检查处理好。
2. `02-后续部署配置教程.md`：按步骤创建 GitHub、Neon、Vercel 并部署。
3. `../zero-basic-vercel-deployment-tutorial.md`：需要更详细截图式步骤时看这份完整教程。
4. `../release-preflight-checklist.md`：部署前和部署后按清单验收。
5. `../backend-api-contract.md`：需要理解后端接口时再看。

## 8. 常见不要做的事

- 不要手动全选整个项目目录重新压缩后再发给别人。
- 不要把 `.git/`、`node_modules/`、`dist/`、`coverage/`、`.vercel/`、`output/` 一起发出去。
- 不要把 `.env.local` 或真实密钥发出去。
- 不要在 GitHub 新仓库里先勾选创建 README、`.gitignore` 或 license；这个项目已经有这些配置。
- 不要跳过 `npm run verify`，否则部署失败时很难判断是代码问题还是平台配置问题。
